# 需求文档

## 项目介绍
本项目是一个Http业务学习项目，旨在将服务器运维涉及到的相关功能进行拆分，并通过最终集成到Http服务的方式，学习网络业务开发。

后端基于 **Rust Rocket 框架** 构建。项目采用模块化设计，将后端功能拆分为多个独立模块。每个模块仅对外暴露必要的操控接口，模块间通过接口调用实现解耦。Rocket 框架本身处理路由注册、请求分发、中间件（Fairing）、请求守卫（Request Guard）等通用HTTP层能力，业务模块仅需关注自身的核心逻辑并通过 Rocket 的 `mount`/`manage` 机制挂载。

## 各阶段需求

### (P0)HTTP服务基础框架模块（Rocket框架层）

    功能定位：基于Rocket框架搭建HTTP服务，负责服务的启动配置、路由挂载、状态管理与全局中间件。该模块不包含业务逻辑，仅通过Rocket的 `rocket::build()` → `mount()` → `manage()` → `attach()` 流程，将各业务模块的路由和共享状态接入框架。路由注册、请求分发、JSON序列化等通用能力由Rocket框架原生提供。
    
    1. 基于 `Rocket.toml` 实现服务配置，包括监听地址/端口、Worker线程数、Keep-Alive超时、TLS证书路径等Rocket原生配置项；
    2. 利用Rocket的 `#[launch]` 宏或 `rocket::build()` 启动服务，各业务模块的路由通过 `.mount(base_path, routes![...])` 挂载到对应路径前缀；
    3. 利用Rocket内建的 `serde_json` + `Responder` 机制，定义统一的JSON响应结构体（`ApiResponse<T>`），包含code、message、data字段，各业务Handler直接返回该结构体；
    4. 利用Rocket Fairing机制实现全局中间件：请求日志Fairing、CORS处理Fairing、异常捕获Catcher，通过 `.attach(Fairing)` 注册；
    5. 利用Rocket的 `State<T>` 管理机制实现模块间共享状态，各业务模块的实例通过 `.manage(instance)` 注入Rocket，在路由Handler中通过 `State<Module>` 参数获取；
    6. 利用Rocket的 `FileServer` 实现静态文件服务，托管前端页面资源，通过 `.mount("/", FileServer::from(static_dir))` 挂载；
    7. 利用Rocket的 SSE（Server-Sent Events）实现实时数据推送（替代WebSocket），通过返回 `EventStream` 类型的Response实现服务器状态实时更新；
    8. 利用Rocket内建的 `Catcher` 机制统一处理404、422、500等HTTP错误，返回统一格式的错误响应；

### (P0)服务器状态监控模块

    功能定位：采集服务器主机的实时运行状态数据，对外提供查询接口。该模块不包含网络通信逻辑，仅负责数据采集与聚合，供HTTP模块调用。该模块直接操控操作系统层面的资源指标。

    1. 实现CPU状态监控，采集CPU型号、核心数、使用率（总体/每核）、频率、温度等信息；
    2. 实现内存状态监控，采集总内存、已用内存、可用内存、Swap使用情况等信息；
    3. 实现磁盘状态监控，采集磁盘列表、各分区总量/已用/可用、读写速率、磁盘健康状态（S.M.A.R.T）等信息；
    4. 实现网络状态监控，采集网络接口列表、各接口实时上下行速率、总收发字节数、网络连接数等信息；
    5. 实现系统负载监控，采集系统运行时间、1/5/15分钟平均负载等信息；
    6. 提供定时采集机制，支持可配置的采集间隔，采集数据缓存于内存供查询；
    7. 暴露统一的数据查询接口，返回结构化的状态数据，供HTTP模块调用；

### (P0)用户管理模块

    功能定位：管理浏览器网页端用户的账户信息，提供用户的增删改查基础操作。该模块不包含权限逻辑，仅关注账户本身的生命周期管理。

    1. 实现用户注册功能，包含用户名、密码、邮箱等基础字段；
    2. 实现用户登录功能，支持基于Token（JWT）的认证机制；
    3. 实现用户信息的查看与修改（个人信息、密码修改等）；
    4. 实现用户账户的启用/禁用功能；
    5. 实现用户列表查询，支持分页及关键字搜索；
    6. 实现用户密码的加密存储（bcrypt或等效方案）；
    7. 实现登录会话管理，支持Token过期、刷新、主动登出等能力；
    8. 暴露用户管理的操控接口，供HTTP模块和权限模块调用；

### (P1)用户权限管理模块

    功能定位：基于RBAC（基于角色的访问控制）模型，管理用户对系统各功能模块的访问权限。该模块依赖用户管理模块提供的用户信息。权限校验通过Rocket的 **Request Guard** 机制实现：定义自定义Guard类型（如 `AuthGuard`），在每个需要鉴权的路由Handler参数中声明该Guard，Rocket会在进入Handler前自动完成鉴权，鉴权失败则直接返回Forbidden响应，无需在路由函数体内重复编写鉴权逻辑。

    1. 实现角色管理，支持角色的创建、删除、修改、列表查询；
    2. 实现权限项（Permission）的定义与管理，每个权限项对应一个具体的功能操作（如：查看CPU状态、创建子进程、管理frpc隧道等）；
    3. 实现角色与权限项的绑定与解绑，一个角色可拥有多个权限项；
    4. 实现用户与角色的绑定与解绑，一个用户可拥有多个角色；
    5. 实现自定义Rocket Request Guard（如 `AuthGuard`），Guard内部从请求Header中提取JWT Token，解析用户身份，查询用户权限，校验是否具备当前路由所需权限；Guard在路由Handler参数中声明即可自动生效，例如 `fn handler(auth: AuthGuard, ...)`；
    6. 实现默认角色的初始化（如：admin超级管理员、operator运维人员、viewer只读用户），系统首次启动时自动创建；
    7. 实现权限变更的即时生效，无需重启服务（Guard每次请求时实时查询权限，不缓存）；
    8. 各业务模块的路由Handler通过在函数签名中声明 `AuthGuard`（或更细粒度的 `PermissionGuard<"perm_name">`）即可实现声明式鉴权，无需显式调用权限校验接口；

### (P1)子进程管理模块

    功能定位：管理由本系统创建的子进程（如启动一个长期运行的服务、执行一个脚本等），提供进程的全生命周期管理。该模块与子任务管理模块配合，为上层业务提供进程级的操控能力。

    1. 实现子进程的创建，支持配置启动命令、工作目录、环境变量、标准输出/错误重定向；
    2. 实现子进程的终止，支持优雅关闭（SIGTERM）和强制终止（SIGKILL）两种模式；
    3. 实现子进程的状态查询，包括运行中、已退出、已终止等状态，以及退出码、运行时长等信息；
    4. 实现子进程的实时输出日志获取，支持读取标准输出和标准错误的最近N行内容；
    5. 实现子进程的保活（Keep-Alive）机制，当进程异常退出时自动重启，支持配置最大重试次数和重启间隔；
    6. 实现子进程的资源使用监控，采集该进程的CPU、内存占用；
    7. 实现子进程的启动/停止/重启的API接口；
    8. 暴露进程管理操控接口，供HTTP模块和子任务管理模块调用；

### (P1)子任务管理模块

    功能定位：提供异步任务的创建、调度与执行追踪能力。该模块在子进程管理模块之上构建，将一次完整的业务操作封装为一个"任务"，支持任务队列、并发控制与状态追踪。

    1. 实现任务的定义与创建，任务包含：任务名称、任务类型、执行参数、优先级、超时时间等属性；
    2. 实现任务的状态追踪，支持状态流转：待执行 → 执行中 → 已完成/已失败/已取消；
    3. 实现任务队列机制，支持优先级排序和FIFO调度；
    4. 实现任务并发控制，支持配置最大并发执行数；
    5. 实现任务的取消操作，对正在执行的任务通过子进程管理模块终止对应进程；
    6. 实现任务的执行日志记录，记录任务开始时间、结束时间、执行结果、错误信息等；
    7. 实现任务历史查询，支持按状态、时间范围、任务类型等条件筛选，支持分页；
    8. 实现任务执行超时自动终止，超时时间可配置，超时后自动调用子进程终止接口；
    9. 暴露任务管理操控接口，供HTTP模块调用；

### (P2)网络管理模块（Frpc管理）

    功能定位：管理Frpc（Fast Reverse Proxy Client）隧道配置与运行，实现内网穿透能力。该模块依赖子进程管理模块来运行frpc客户端进程，并向用户提供隧道的配置与管理界面。

    1. 实现Frpc隧道的配置管理，支持创建、修改、删除隧道配置，隧道配置包含：隧道名称、协议类型（TCP/UDP/HTTP/HTTPS）、本地IP、本地端口、远程端口、自定义域名、加密、压缩等参数；
    2. 实现Frpc配置文件的持久化存储，将隧道配置保存为frpc可识别的配置文件格式；
    3. 实现Frpc客户端的启停管理，通过子进程管理模块启动/停止frpc进程，并监控其运行状态；
    4. 实现隧道连接状态的实时监控，显示各隧道的在线状态、连接时长、实时流量等信息；
    5. 实现隧道流量的统计功能，记录每个隧道的历史流量数据（日/周/月维度）；
    6. 实现隧道配置的导入/导出功能，支持迁移或备份隧道配置；
    7. 实现隧道异常告警，当隧道连接断开或异常时自动记录告警信息；
    8. 暴露网络管理操控接口，供HTTP模块调用；

## 模块间依赖关系

```
Rocket 框架层
│  #[launch] rocket::build()
│  ┌─ .mount()     → 挂载各模块路由
│  ├─ .manage()    → 注入模块实例(State<T>)
│  ├─ .attach()    → 注册全局Fairing(日志/CORS/鉴权)
│  └─ .register()  → 注册Catcher(错误处理)
│
├── 服务器状态监控模块 (P0)   [独立模块，无内部依赖]
├── 用户管理模块 (P0)         [独立模块，无内部依赖]
├── 用户权限管理模块 (P1)     [依赖：用户管理模块；通过Request Guard集成到Rocket]
├── 子进程管理模块 (P1)       [独立模块，无内部依赖]
├── 子任务管理模块 (P1)       [依赖：子进程管理模块]
└── 网络管理模块(Frpc) (P2)   [依赖：子进程管理模块]
```

## Rocket框架路由规划

|模块|Rocket mount路径|路由示例|说明|
|----|----|----|----|
|登录（公开）|`/api/auth`|`#[post("/login")]`|登录接口，不需要鉴权|
|服务器状态监控|`/api/status`|`#[get("/cpu")]`|CPU、内存、磁盘、网络状态查询|
|用户管理|`/api/user`|`#[get("/list")]`|注册、用户CRUD|
|角色管理|`/api/role`|`#[get("/list")]`|角色CRUD|
|权限管理|`/api/permission`|`#[get("/list")]`|权限项CRUD|
|子进程管理|`/api/process`|`#[get("/list")]`|进程CRUD与状态查询|
|子任务管理|`/api/task`|`#[get("/list")]`|任务CRUD与状态追踪|
|网络管理(Frpc)|`/api/network`|`#[get("/tunnels")]`|隧道配置与监控|

> **鉴权说明**：除 `/api/auth/login` 外，所有路由均通过在Handler函数签名中声明 `AuthGuard` 实现鉴权。部分敏感操作（如删除用户、管理frpc隧道）需额外声明 `PermissionGuard` 进行细粒度权限校验。鉴权失败时由Guard返回 `401 Unauthorized` 或 `403 Forbidden`，业务Handler函数体内无需处理鉴权逻辑。
